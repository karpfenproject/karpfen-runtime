# 3.6 Examples

The folder `examples` of the runtime holds four example models that have nothing to do with lamps. Each of their
folders has a metamodel, a model, one state machine, the event definitions in `EVENTS.kmeta` and a `README.md` with
the steps to run the example.

The developer document
[The HTTP API of the runtime](https://github.com/karpfenproject/karpfen-runtime/blob/main/docs/http-api.md#running-an-example)
on GitHub has the shell commands and the event that run the autonomous car by the steps at the end of this chapter.

The example projects about lamps belong to the IDE.

| Folder of the IDE | Example project | What it holds |
|---|---|---|
| `examples/lamp` | The lamp example project | A lamp and its wall switch |
| `examples/spares` | The spares example project | A room with spare bulbs that get their state machine instances at run time by the rules of [3.1.13 State machine management and lifecycle](3.1-execution-semantics.md#3113-state-machine-management-and-lifecycle) |
| `examples/pages` | The pages example project | A lamp whose state machine is composed of fragments |

| Folder | What it shows | Object of the state machine | Events |
|---|---|---|---|
| `single_robot_example` | A cleaning robot that drives around a room and steers away from obstacles and walls. Nested states, `NOT LOOPING`, `EVAL` conditions, `SETOBJ` on a `knows` relation, `WITH ... AS`, macros with `numpy`, events raised by the state machine | `turtle` | `start` in domain `public`. `EVENTS.kmeta` also defines `setSpeed` and `teleport`, but the state machine does not use them |
| `delivery_drone_example` | A delivery drone driven by events with payloads. Conditions on payload fields, `$(event->...)` in ENTRY blocks, `IF IN SCOPE`, payload values copied into the model | `scout` | `assignDelivery`, `setCruiseSpeed`, `recall` in domain `control` |
| `autonomous_car_example` | A car that tests three subsystems in parallel before it drives. `SPLIT` into three branches and `JOIN` back | `av-1` | `powerOn` in domain `ignition` |
| `drone_swarm_example` | A swarm that grows, reshapes and shrinks its fleet. `APPENDOBJ`, `SETOBJ`, `DROPOBJ`, `SETLIST`, `DROPLIST`, `WITH ... AS` | `alpha-swarm` | `deploy`, `droneDown`, `recall` in domain `swarm` |

| Folder | Files |
|---|---|
| `single_robot_example` | `cleaning_robot.kmeta`, `cleaning_robot.kmodel`, `cleaning_robot.kstates`, `EVENTS.kmeta` |
| `delivery_drone_example` | `delivery_drone.kmeta`, `delivery_drone.kmodel`, `delivery_drone.kstates`, `EVENTS.kmeta` |
| `autonomous_car_example` | `autonomous_car.kmeta`, `autonomous_car.kmodel`, `autonomous_car.kstates`, `EVENTS.kmeta` |
| `drone_swarm_example` | `drone_swarm.kmeta`, `drone_swarm.kmodel`, `drone_swarm.kstates`, `EVENTS.kmeta` |

All four examples use `EVAL` blocks or macros and need Python at hand when they run. The macros of the robot also
import `numpy`. The Docker image of [3.3.3 Running in Docker](3.3-running-the-runtime.md#333-running-in-docker)
brings both.

An example runs in five steps, given here for the car. The routes are those of [3.4 HTTP API](3.4-http-api.md).

1. Start the runtime in one of the ways of [3.3 Running the runtime](3.3-running-the-runtime.md).
2. In the folder of the example, create an environment with `createEnvironment` and upload the files. The metamodel
   `autonomous_car.kmeta` goes to `setMetamodel`, the model `autonomous_car.kmodel` to `setModel` and `EVENTS.kmeta`
   to `setEventDefinitions`. The state machine `autonomous_car.kstates` goes to `setStateMachine` with
   `attachedTo=av-1`. A call of `setTickDelay` sets the tick delay to 300 ms.
3. Register a WebSocket client `viewer` with `registerClientForWebSocket` and make it an observer of `av-1`, the
   object of the state machine, with `registerObjectObserver`.
4. Run and start the environment with `runEnvironment` and `startEnvironment`.
5. Connect the client to `ws://127.0.0.1:8080/ws`, send `viewer:<envKey>:<accessKey>` as the first frame, and then
   send the event that starts the example. For the car that is `powerOn` in the domain `ignition` with an empty
   payload.

From then on the client gets `objectChanged` for the car each time an action block changes it. The `README.md` of
each example names the events it takes and their payloads. The developer document
[The WebSocket of the runtime](https://github.com/karpfenproject/karpfen-runtime/blob/main/docs/websocket.md)
describes the connection and the messages in full.

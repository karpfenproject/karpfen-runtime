# 3.5 WebSocket

Over the WebSocket at `ws://127.0.0.1:8080/ws` a client sends events to an environment and gets the changes of the
run pushed as they happen. Host and port are those of
[3.3.4 Configuration](3.3-running-the-runtime.md#334-configuration), the same as for the
[3.4 HTTP API](3.4-http-api.md).
Like the HTTP API, the WebSocket is there for someone who writes a client of the runtime. A user of the IDE does not
need it, because the IDE connects on its own when a project runs.

Before a client connects, it registers over HTTP and gets an access key that works for one connection only. It then
opens the WebSocket and sends its client id, the key of the environment and the access key in its first frame. All
frames are text frames, and every frame after the first holds a JSON object. The connection stays open while the
environment is stopped and started again. It closes when the environment is dropped or the runtime ends.

An event that a client sends names its domain, its name and an optional payload in JSON or KModel. It reaches the
state machines of the environment by the rules of [3.1.7 Events](3.1-execution-semantics.md#317-events). Events sent
before `runEnvironment` are dropped. Events sent after it and before the start wait for the start.

Apart from the status of the run, which goes to every connected client, the runtime pushes a message only for what
the client registered for. The messages are of four kinds.

- changes of the objects that the client observes, or of every object when it subscribed to the whole model
- changes of the active states of state machines, and state machine instances that join or leave
- events of the domains that the client listens to
- the status of the run: a pause or a halt at a breakpoint, a stop and a start

Changes of objects and of state machines carry a revision that the environment counts from 1. With the revisions a
client keeps a complete copy of the model from one snapshot over HTTP and the messages that come after it.

The developer document
[The WebSocket of the runtime](https://github.com/karpfenproject/karpfen-runtime/blob/main/docs/websocket.md)
on GitHub describes every frame and message with its entries and rules and shows an example of each.

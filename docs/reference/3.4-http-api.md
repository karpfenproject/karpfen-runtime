# 3.4 HTTP API

A client drives the runtime over HTTP. With the routes of the API it creates an environment, uploads the metamodel,
the model, the event definitions and the state machines, runs the environment and registers for the messages of
[3.5 WebSocket](3.5-websocket.md). The API is there for someone who writes a client of the runtime. A user of the IDE
never needs it, because the IDE makes these calls on its own when a project runs.

The runtime listens by default at `http://127.0.0.1:8080`, on the address and port of
[3.3.4 Configuration](3.3-running-the-runtime.md#334-configuration). Parameters go in the query string. Uploads and
messages to features go in the body as plain text. Most routes name the environment they act on with the parameter
`envKey`, the key that the runtime handed out when it created the environment.

A successful call answers with status 200. A failed call answers with a status and gives the reason as plain text in
the body. Status 400 stands for a wrong or missing parameter, an unknown environment or an upload with errors, and in
the case of an upload the body names every error with its line and column. Status 409 means that the call does not fit
the phase of the environment, for example an upload after the environment was run. The phases and the order of the
calls in the life of an environment are described in [3 Execution](3-execution.md).

| Group | What a client does with it |
|---|---|
| Environments | Creates an environment and drops it when it no longer needs it |
| Uploads | Sends the metamodel, the model, the event definitions and the state machines while the environment is in the phase `configuring` |
| Settings | Sets the tick delay, the time to live of events and the result cache of an environment |
| Clients | Registers a client for the WebSocket and chooses the objects and event domains it hears about |
| Running | Activates, starts and stops the environment and forces a state machine into a state |
| Observation | Reads a snapshot of the model, the state machines of the environment and the numbers of a run |
| Health | Asks whether the runtime is up |
| Features | Switches the features of [3.2 Runtime features](3.2-features.md) on and off and sends them messages |

Every route with its parameters, its answers and its refusals is described in the developer document
[The HTTP API of the runtime](https://github.com/karpfenproject/karpfen-runtime/blob/main/docs/http-api.md) on GitHub.
It also shows each call as a `curl` command for the lamp example project, together with the answer of the runtime.
